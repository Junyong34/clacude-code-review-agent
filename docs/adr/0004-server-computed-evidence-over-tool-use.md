# 리뷰 컨텍스트 확장은 tool use 대신 서버 계산 증거 주입으로 한다

리뷰가 함수 단위에 머무는 원인은 SDK나 스킬이 아니라 입력 구성이었다. diff 컨텍스트 라인은 3줄로 잘려 있었고, `[REF]` 힌트는 파일 경로만 담았다. 외부 코드리뷰 스킬(`skills/evidence-code-review`)은 호출자 검색·파일 읽기·서브 에이전트 위임을 전제로 하는데, 현재 호출은 도구 없는 단발 `messages.stream`이다.

Claude에게 읽기 전용 도구(`read_file`, `grep`, CRG 질의)를 열어 에이전트 루프를 돌리는 대신, **서버가 결정론적으로 계산한 증거를 리뷰 입력에 주입**한다. 컨텍스트 라인 확장, 그리고 CRG의 `edges`/`nodes`로 찾은 호출부 스니펫(master 워크트리에서 읽음)이 그것이다. 스킬은 런타임에 로드하지 않고, diff와 서버 증거만으로 판단 가능한 기준만 증류해 시스템 프롬프트에 넣는다. 출력은 P1~P5와 기존 JSON 스키마를 유지한다.

서버 증거는 변경 라인에서 확인된 시그니처 변경과 함께 있을 때 P1·P2의 근거로 인정한다. 코멘트 앵커는 계속 변경 라인(ADD/REM)에 둔다. 인터페이스 변경 판정이 `unknown`이면 P5까지만 허용한다.

## Considered Options

- **스킬 전문을 시스템 프롬프트에 삽입**: 도구가 없는 모델에게 도구 전제 지시를 주게 되어 검증한 척하는 환각이 늘어난다.
- **읽기 전용 tool use 도입**: 호출 지연·비용 증가, `claudeStreamLimiter` 동시성과 `budget_exceeded` 설계 재검토가 필요하고, 워크트리가 master 기준이라 PR 브랜치의 신규 파일은 읽을 수 없다. 서버 증거로 부족하다고 확인되면 재검토한다.

## Consequences

- 호출부 스니펫은 master 기준이므로 PR에서 새로 추가된 코드의 호출부는 증거에 포함되지 않는다.
- 입력이 커지므로 상한(100,000자)과 절단 우선순위(변경 라인·인접 3줄 → 확장 컨텍스트 → 호출부 스니펫)를 둔다.
- 모델과 effort를 `claude-sonnet-5-5`, `medium`으로 올리면서 지연과 비용이 늘어난다.
